# Shepherd AI — Datasets

## Overview

Shepherd AI relies on several open-source and public-domain datasets to populate its Bible text, cross-references, and study notes. These datasets are ingested into the PostgreSQL database via one-time seed edge functions (`seed-bible`, `seed-cross-refs`, `seed-study-notes`, `seed-study-notes-ai`). This document catalogs each dataset source, its purpose, and planned future expansions.

## Current Datasets

### Bible Text

#### thiagobodruk/bible

- **Source:** https://github.com/thiagobodruk/bible
- **Purpose:** Primary source for Bible verse text. Provides the full canonical text in structured JSON format, organized by book, chapter, and verse.
- **Used by:** `seed-bible` edge function
- **Storage:** `bible_verses` table (`book`, `chapter`, `verse`, `text`, `translation`)

#### seven1m/open-bibles

- **Source:** https://github.com/seven1m/open-bibles
- **Purpose:** Supplementary Bible text source. Provides multiple public-domain translations in a structured format suitable for bulk import.
- **Used by:** `seed-bible` edge function
- **Storage:** `bible_verses` table

### Cross-References

#### openbibleinfo/Bible-Cross-References

- **Source:** https://github.com/openbibleinfo/Bible-Cross-References
- **Purpose:** Maps relationships between Bible verses across books and testaments. Cross-references are used in the RAG pipeline to expand the context beyond the directly matched verses, giving the AI model a broader scriptural foundation. They also appear in verse deep-dive views and prayer generation.
- **Used by:** `seed-cross-refs` edge function
- **Storage:** `cross_references` table (`from_verse_id`, `to_verse_id`, `votes`)
- **Scale:** Tens of thousands of verse-to-verse relationships with community vote counts indicating strength of connection.

### Study Notes

#### Tyndale Open Study Notes

- **Source:** Tyndale House Publishers (open-licensed)
- **Purpose:** Provides scholarly commentary and explanatory notes for Bible verses. These notes are injected into the RAG pipeline alongside retrieved verses, giving the AI model expert theological context to inform its explanations. Study notes help bridge the gap between raw verse text and practical application.
- **Used by:** `seed-study-notes` edge function
- **Storage:** `study_notes` table (`verse_id`, `source`, `note_text`)
- **Coverage:** Partial — not all verses have study notes. The `seed-study-notes-ai` function generates AI-written notes to supplement gaps in coverage.

#### AI-Generated Study Notes

- **Source:** Generated by the system using the Lovable AI Gateway
- **Purpose:** Fills gaps in Tyndale Open Study Notes coverage. For verses without existing study notes, the `seed-study-notes-ai` edge function generates commentary using the AI model, ensuring broader coverage across the Bible.
- **Used by:** `seed-study-notes-ai` edge function
- **Storage:** `study_notes` table (with source marked as AI-generated)

### Vector Embeddings

- **Source:** Generated by the system using the `embed-bible` edge function
- **Purpose:** Creates pgvector embeddings for Bible verses to enable semantic similarity search. Embeddings are stored in the `embedding` column of the `bible_verses` table.
- **Used by:** `embed-bible` edge function
- **Storage:** `bible_verses.embedding` column (vector type)

## Future Dataset Expansion

The following datasets are planned for future integration to deepen the system's biblical scholarship capabilities:

### Hebrew Morphology

#### Open Scriptures Hebrew Bible (OSHB)

- **Source:** https://github.com/openscriptures/morphhb
- **Purpose:** Provides morphological analysis of the Hebrew Old Testament, including word-by-word parsing with lemmas, parts of speech, and grammatical features. Would enable Hebrew word studies and deeper Old Testament analysis.

#### Macula Hebrew

- **Source:** https://github.com/Clear-Bible/macula-hebrew
- **Purpose:** Syntactic and discourse analysis of the Hebrew Bible. Provides clause-level parsing, discourse relationships, and semantic annotations. Would enable the AI to explain Hebrew sentence structure and discourse flow.

### Greek Analysis

#### Macula Greek

- **Source:** https://github.com/Clear-Bible/macula-greek
- **Purpose:** Syntactic and discourse analysis of the Greek New Testament. Provides word-level morphology, clause structure, and discourse annotations. Would enable Greek word studies and deeper New Testament analysis.

#### Greek Lemma Datasets

- **Purpose:** Lexical data mapping Greek New Testament words to their dictionary forms (lemmas) with definitions, usage frequencies, and semantic domains. Would power features like "What does this word mean in the original Greek?"

### Biblical Lexicons

- **Purpose:** Hebrew and Greek lexicon data providing dictionary definitions, semantic ranges, and usage examples for biblical vocabulary. Would enable the AI to reference original-language word meanings when explaining verses, adding scholarly depth to responses.

## Dataset Ingestion Architecture

```
Dataset (GitHub/static) → Seed Edge Function → PostgreSQL Table
                                                      │
                                                      ▼
                                              Embed Edge Function
                                                      │
                                                      ▼
                                              pgvector Embeddings
```

All datasets flow through dedicated seed edge functions that handle parsing, validation, and bulk insertion. The `embed-bible` function runs as a separate step after seeding to generate vector embeddings. Seed functions are idempotent and designed for one-time use during initial setup or data refresh.
