# Shepherd AI — System Architecture

## Overview

Shepherd AI is a React single-page application backed by Supabase (database, auth, edge functions). AI responses are generated by Google Gemini models accessed through OpenRouter. The core design principle is retrieval-augmented generation: scripture and supporting data are retrieved from the database and injected into prompts so that AI responses are grounded in actual Bible text.

```
┌─────────────┐     ┌──────────────────┐     ┌─────────────────────┐
│   Browser    │────▶│  Supabase Edge   │────▶│     OpenRouter      │
│  React SPA   │◀────│    Functions     │◀────│   (Google Gemini)   │
└─────────────┘     └──────────────────┘     └─────────────────────┘
                           │  ▲
                           ▼  │
                    ┌──────────────────┐
                    │    PostgreSQL     │
                    │  (Supabase DB)   │
                    │  + pgvector      │
                    └──────────────────┘
```

## 1. Frontend

### Location

All frontend source code lives in `src/`.

### Routing

The app uses `react-router-dom` v6 with the following routes defined in `src/App.tsx`:

| Route | Component | Auth Required | Description |
|---|---|---|---|
| `/` | `Index` | No | Landing page |
| `/chat` | `ChatPage` | No | Conversational AI chat with SSE streaming |
| `/prayer` | `PrayerPage` | No | Emotion-based prayer generation |
| `/devotional` | `DevotionalPage` | No | Multi-day devotional creation |
| `/verse` | `VersePage` | No | Verse deep-dive with context |
| `/explore` | `ExplorePage` | No | Bible browser (book / chapter / verse) |
| `/dashboard` | `DashboardPage` | Yes | Personal spiritual dashboard |
| `/settings` | `SettingsPage` | Yes | User profile and preferences |
| `/auth` | `AuthPage` | No | Sign in / sign up |

Auth-guarded routes are wrapped in `AuthGuard`, which redirects unauthenticated users.

### Key Pages

- **ChatPage** (`src/pages/ChatPage.tsx`) — The primary interface. Users send messages and receive SSE-streamed AI responses grounded in retrieved scripture. Supports quick prompts, crisis detection, verse bookmarking from chat, and memory-based personalization hints.
- **PrayerPage** (`src/pages/PrayerPage.tsx`) — Users select an emotion and receive a scripture-based prayer with verse references, a reflection question, and cross-references. Prayers can be saved to the prayer journal.
- **DevotionalPage** (`src/pages/DevotionalPage.tsx`) — Generates multi-day devotional plans (1–14 days) on a chosen topic. Each day includes a verse, explanation, reflection, and prayer.
- **ExplorePage** (`src/pages/ExplorePage.tsx`) — Full Bible browser. Navigate by book, chapter, and verse. The largest page component (~671 lines).
- **VersePage** (`src/pages/VersePage.tsx`) — Deep-dive into a single verse with surrounding passage context, cross-references, study notes, and book-level context.
- **DashboardPage** (`src/pages/DashboardPage.tsx`) — Personal spiritual dashboard showing saved verses, prayer journal entries, devotionals, and engagement history.

### Frontend AI Client

`src/lib/ai.ts` exports three functions that call edge functions:

| Function | Edge Function | Response Format |
|---|---|---|
| `streamChat()` | `/functions/v1/chat` | SSE stream (parsed line-by-line) |
| `generatePrayer()` | `/functions/v1/prayer` | JSON |
| `generateDevotional()` | `/functions/v1/devotional` | JSON |

All requests authenticate with `VITE_SUPABASE_PUBLISHABLE_KEY` as a Bearer token.

### Spiritual Memory System

`src/lib/memories.ts` handles client-side memory extraction:

- `extractThemes(text)` — Matches user messages against 10 theme categories (anxiety, forgiveness, guidance, hope, grief, anger, gratitude, peace, love, strength).
- `extractVerseRefs(text)` — Regex-extracts bold verse references (e.g., `**Isaiah 41:10**`) from AI responses.
- `upsertMemories(userId, userMessage, aiResponse)` — For each theme-verse pair found, inserts or increments frequency in the `user_memories` table (capped at 3 verses per theme).

Memories are loaded at chat start and sent to the edge function for personalization.

### Other Notable Components

| Component | Purpose |
|---|---|
| `AuthGuard` | Route protection for authenticated pages |
| `CrisisBanner` | Displays mental health resources when crisis language is detected |
| `ErrorBoundary` | Catches and displays React rendering errors |
| `Navbar` | Global navigation bar |
| `PrayerCard` | Shareable prayer card with image export via html-to-image |

## 2. Backend — Supabase Edge Functions

### Location

All edge functions live in `supabase/functions/`. Each function has its own directory with an `index.ts` entry point. Shared utilities are in `supabase/functions/_shared/`.

### AI-Facing Functions

| Function | Purpose | Model | Response |
|---|---|---|---|
| `chat` | RAG-powered conversational chat | `MODEL_CHAT` (default `google/gemini-3-flash-preview`) | SSE stream |
| `prayer` | Emotion/topic prayer generation with DB verses | `MODEL_PRAYER` (default `anthropic/claude-haiku-4.5`) | JSON (structured) |
| `devotional` | Multi-day devotional generation seeded from DB verses | `MODEL_DEVOTIONAL` (default `anthropic/claude-haiku-4.5`) | JSON (structured) |
| `verse-context` | Single verse deep-dive with authoritative DB text | `MODEL_VERSE_CONTEXT` (default `google/gemini-3-flash-preview`) | JSON (structured) |

### Data Ingestion Functions (One-Time Use)

| Function | Purpose |
|---|---|
| `seed-bible` | Populates `bible_verses` table from source datasets |
| `embed-bible` | Generates pgvector embeddings for Bible verses |
| `seed-cross-refs` | Populates `cross_references` table |
| `seed-study-notes` | Populates `study_notes` from static data |
| `seed-study-notes-ai` | Generates AI-written study notes for uncovered verses |

### Shared Modules

- `_shared/cors.ts` — CORS headers and preflight request handler used by all functions.
- `_shared/env.ts` — model policy and environment/config loading.
- `_shared/ai.ts` — shared OpenRouter wrappers (`generateJson`, `generateText`, `streamText`, `withRetry`, `safeParseJson`).
- `_shared/retrieval.ts` — shared scripture retrieval helpers for verse lookup/search/cross-refs/study notes/theme retrieval.
- `_shared/schema.ts` — request/response validation helpers.
- `_shared/errors.ts` — normalized edge function error and response handling.
- `_shared/reference.ts` — verse reference parsing/format helpers.
- `_shared/admin-auth.ts` — admin authentication helper for protected seed operations.

## 3. Database

### Platform

PostgreSQL hosted by Supabase with the `pgvector` extension enabled for vector similarity search. Row-level security (RLS) is enabled on all user-facing tables.

### Schema

| Table | Purpose | Key Columns |
|---|---|---|
| `bible_verses` | Canonical Bible text | `book`, `chapter`, `verse_number`, `text`, `fts`, `embedding` |
| `cross_references` | Verse-to-verse relationships | `from_verse`, `to_verse`, `weight` |
| `study_notes` | Commentary and notes per verse | `verse_reference`, `note_text` |
| `profiles` | User profile data | `user_id` (FK to auth.users), `display_name`, `avatar_url` |
| `conversations` | Chat history | `user_id`, `message`, `response`, `themes` |
| `saved_verses` | User-bookmarked verses | `user_id`, `verse_reference`, `verse_text`, `note`, `theme` |
| `saved_devotionals` | Saved devotional plans | `user_id`, `topic`, `days_count`, `devotional_json` |
| `prayer_journal` | Prayer entries | `user_id`, `emotion`, `verse_reference`, `prayer_text`, `reflection` |
| `daily_checkins` | Spiritual check-ins | `user_id`, `emotion`, `created_at` |
| `user_memories` | Theme × verse memory graph | `user_id`, `theme`, `verse_reference`, `frequency`, `confidence`, `first_seen_at`, `last_seen_at`, `concerns`, `spiritual_goals`, `source_type` |

### Key Relationships

- `profiles.user_id` → `auth.users.id` (auto-created on signup via database trigger)
- `cross_references` and `study_notes` reference verse text entries by normalized verse-reference strings.
- All user-facing tables have `user_id` → `auth.users.id` with RLS policies restricting access to own data

### Database Functions

- `search_verses(query_text)` — Full-text search RPC used by the RAG pipeline to find relevant Bible verses.
- `handle_new_user()` — Trigger function that auto-creates a `profiles` row when a new user signs up.
- `update_updated_at_column()` — Trigger function for automatic timestamp maintenance.

### Migrations

All schema changes are tracked in `supabase/migrations/` as timestamped SQL files.

## 4. AI Layer

### Gateway

All AI calls route through **OpenRouter** at `https://openrouter.ai/api/v1/chat/completions`. This gateway proxies requests to Google Gemini models. Edge functions authenticate with the gateway using `OPENROUTER_API_KEY`.

### Models

| Model | Used By | Reason |
|---|---|---|
| `MODEL_CHAT` | chat | Streaming chat model (default `google/gemini-3-flash-preview`) |
| `MODEL_PRAYER` | prayer | Structured-output prayer model (default `anthropic/claude-haiku-4.5`) |
| `MODEL_DEVOTIONAL` | devotional | Structured-output devotional model (default `anthropic/claude-haiku-4.5`) |
| `MODEL_VERSE_CONTEXT` | verse-context | Structured-output verse-context model (default `google/gemini-3-flash-preview`) |

### Response Patterns

- **Chat** — SSE streaming. The edge function pipes the raw stream from the AI gateway back to the browser. The frontend parses `data: {...}` lines and extracts `choices[0].delta.content` tokens.
- **Prayer / Devotional** — Tool calling (function calling). The AI model is given a tool definition and returns structured JSON matching the schema.
- **Verse Context** — Single JSON response with authoritative verse text/passage/references from DB plus AI explanation/application fields.

### Grounding

All AI responses in core flows are grounded in retrieved scripture. `verse-context`, `prayer`, and `devotional` now retrieve authoritative scripture from DB first, then use AI for explanation/application content. Chat also injects retrieved context and user memory into system prompts.
